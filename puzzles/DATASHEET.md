# Datasheet: certified-puzzle probe family (`puzzles/`)

Structure follows "Datasheets for Datasets" (Gebru et al., 2021) and the
datasheet discipline of the certified logic-puzzle benchmark of
Behnamian et al., "Fair but hard: certified unique-solution puzzles
generated by language models" (Lund University, 2026).

## Motivation

A contamination-proof reasoning probe for the estate battery. Benchmark
items that circulate become training data; items that are regenerated
fresh, carry a solver certificate of a unique answer, and are
clue-minimal do not. This family exists to measure estate models on
logic reasoning that no model can have memorized, because the instances
are born after the model froze.

## Method (generate -> encode -> certify)

1. **generate**: a ground-truth solution is sampled from a seeded
   generator (zebra: seeded permutations per category; futoshiki: a
   seeded Latin square — see *Limitations*).
2. **encode**: candidate clues true under the solution enter a pool;
   clues are added in seeded order until the puzzle becomes unique.
3. **certify**: uniqueness is proven by enumeration — solve, block the
   solution, re-solve to exhaustion — under **two independent CNF
   encodings** (direct forbidden-tuple encoding and a support
   / value-position encoding), and the solution must additionally pass
   a declarative predicate check (`CSP.check`) that never touches CNF.
   Three independent paths must agree before any prompt is issued.
4. **minimize**: every clue whose removal keeps the solution unique is
   dropped; shipped puzzles are clue-minimal by construction, and the
   test suite re-verifies minimality independently.

The SAT engine is a small deterministic DPLL solver in the Python
standard library (see `puzzles/dpll.py`): no third-party solver, no
platform drift, byte-reproducible certificates on any machine.

## Probing contract (`szl.estate-battery/certified-puzzle-v1`)

- **One puzzle per HTTP call.** Batching puzzles into one prompt
  collapsed solver accuracy in the source study; this family never
  batches.
- **Exact-text evaluation.** The prompt is rendered deterministically
  from the clue predicates and its sha256 is bound into the receipt;
  a score is attached to the bytes that were sent.
- **Honest verdicts.** `PASS` (JSON equals the certified solution),
  `FAIL` (well-formed but wrong), `ABSTAIN` (explicit cannot-determine),
  `ERROR` (transport/parse; listed, never silently scored). The score
  denominator counts attempted (PASS+FAIL+ABSTAIN), not errored, rows.
- **Fail-closed.** No endpoint -> `UNAVAILABLE`, zero rows, exit 2.
  Uncertifiable puzzles are excluded and never sent.
- **Caller-declared model revision**, same policy as the raw engine
  bench: never promotion-eligible on its own.

## Composition

Tiers: `z4` (zebra, 4 houses, 4 categories), `f4` / `f5` (futoshiki,
4x4 / 5x5). Every instance: family, tier, clue list, clue count,
minimal=true, certified solution, content-addressed id (sha256 of the
canonical spec), prompt text and prompt sha256.

## Collection process

No human data, no LLM output in the puzzle content. Clue text is
rendered from fixed templates over the clue predicates.

## Recommended use

`python -m puzzles.probe --seed <n> --plan z4:2,f4:2,f5:1 --model <m>
--model-revision <rev> --source-revision <rev> --out receipt.json`
against any OpenAI-compatible endpoint (`--endpoint-env`), then
`python -m puzzles.make_numbers receipt.json...`. Regenerate with a
fresh seed for contamination-free evaluation; report per-tier accuracy
and abstentions; never pool ERROR rows into accuracy.

## Known limitations

- The futoshiki Latin-square generator samples from a structured family
  (cyclic base + seeded permutations), not uniformly from all Latin
  squares. Certification does not depend on uniformity; zebra solution
  sampling is uniform per category.
- The difficulty construct is clue-minimality, not the five-level
  deduction ladder of the source study. Porting that ladder
  (unit propagation -> GAC -> failed-literal probing -> lookahead ->
  search) is planned follow-up work; the current honest claim is only
  "certified unique + clue-minimal".
- Clue text templates are fixed and public; instances are fresh but
  the genre is known. This limits contamination, it does not eliminate
  genre familiarity.
- LLM-written clues (the E2/E5 stages of the source study) are out of
  scope for v1; only machine-generated, machine-certified instances.
